## Goal / Why
Roadmap row 138 (`cli-group-host`), group `host`. `cli-help-standard` (row 129, merged at `e09d9e05`) added `_command` in `clutch/__main__.py` and the repo-local rules in `CLAUDE.md` section A: every command carries help to the standard through `_command`, every command lives under a top-level group, and a command change updates every document that describes it in the same change. Rows 130-136 built the `engine`, `ticket`, `box`, `config` and `provider` groups that way (row 136 merged at `81f93f59`), and row 137 (`cli-group-view`, confirmed at `d3023443`) builds `view`. At HEAD (`d69f2e35`) `doctor`, `core` and `docs` are still top-level verbs added with a bare `sub.add_parser` and a one-line `help=`, so `clutch help doctor` prints no reads, writes, lock, exit codes or examples. 46 lines of `README.md`, the three conduct files, `clutch/` (the core template, the version-mismatch roads, the doctor rows, the suggested config's header, three ask prompts, the host guides), `docs/how-clutch-works.md` and `tests/` spell them `clutch doctor|core|docs`, and 12 lines of `clutch/` and `tests/` name them in a bare road (`retry core`, `rerun doctor`).

When this ticket is done:
- `clutch host core`, `clutch host docs` and `clutch host doctor` take no arguments, print the same stdout, read the same files, write the same files, take no lock, and exit with the same codes as `clutch core`, `clutch docs` and `clutch doctor` do at HEAD. `host docs` and `host doctor` still run before config loads; `host core` still runs right after the config load and before any checkout, git, lock or journal is built. The only visible differences are the help text, argparse's own usage and error lines, the refusal prefix (`clutch host:`), the roads named in Scope in, and the documents, prompts, conduct block and tests that name these commands (all in Scope in).
- `clutch core`, `clutch docs` and `clutch doctor` no longer parse: argparse exits 2 with an invalid-choice error. There is no alias (`CLAUDE.md` "No dual-path code").
- The `host` group and its three subcommands carry help to the row 129 standard, so the parser walk in `tests/unit/test_main_help.py` checks them.
- Every road that tells an operator to run one of these commands names the new form, including the version-mismatch road every host sees after upgrading clutch: a committed managed block older than the installed template makes `engine drain|serve|run` refuse with ``... clutch core is drifted; run `clutch host core` to refresh the managed block -- run clutch host core, then commit the conduct files and retry engine drain``, and `host doctor`'s `core` row prints the same message.

Why: the owner asked on 2026-11-17 for every command to live under a group with standard help (rows 129-140), so a person or agent setting up a host finds the setup commands together under `clutch help host`, each with what it reads, writes and locks and how it exits. `CLAUDE.md` "Guides name verbs, not command lines" also needs every guide and road to name the verb the CLI accepts. Rows 139-140 move the rest.

Transition, once. Every host's agents read `clutch docs` and `clutch core` from the managed block in `CLAUDE.md` or `AGENTS.md` ("`clutch docs` prints the installed paths of all host guides", "run clutch core to refresh it"). A host whose block was rendered before this release keeps those words after it upgrades clutch, and both commands then exit 2 with an argparse invalid-choice error that lists `host`. Its next `engine drain`, `engine serve` or `engine run` refuses until the block is refreshed, because the installed template changed: the refusal and `clutch host doctor`'s `core` row name `clutch host core`. Run `clutch host core` and commit the routed conduct files; the refreshed block names `clutch host docs` and `clutch host core`. Until then an agent following the old block's `clutch docs` gets exit 2 and can run `clutch host docs`, or read the guide path `clutch ticket new` prints. This repo needs no step: this change refreshes `CLAUDE.md` and `AGENTS.md` in the same commit, so the self-upgrade re-exec's `engine drain` passes the stale-conduct check. A prompt rendered before the merge (`clutch prompt author` and `clutch prompt review` name `clutch docs`; `clutch prompt plan-ticket-drain` names `clutch doctor`) holds the old form; re-render it. A road printed by a process started before the merge ("rerun doctor", "retry core", "run clutch core, then commit the conduct files") names the old form; run the `host` form. The README of an earlier release (including PyPI's) and its host guides name the old forms. No running engine needs a restart: drain and serve never spawn these commands, no lock verb changes, and neither the snapshot nor the VS Code extension names them, so no extension rebuild is needed.
