## Goal / Why
Roadmap row 62, ticket 6 of `docs/evidence-trail-plan.md`. After this ticket a new command group `clutch evidence` has four subcommands over the evidence store. The store already holds raw bytes and envelopes, but nothing writes or reads `normalized/` views and no verb inspects a record.

- `evidence show <call-key>` prints a call's `start.json` and `end.json` and lists its stored normalized views with one line per event (`seq`, `t_ms`, `kind`, `native_type`).
- `evidence schema start|end|event` prints the JSON Schema generated by `clutch.evidence.schema.json_schema`, so tools outside clutch can validate records.
- `evidence renormalize [--prefix KEY_PREFIX]` runs the current normalizer for each stored call's provider over its stored raw stdout and writes `calls/<escaped key>/normalized/<escaped normalizer id>.json`. Older views from other normalizer ids stay beside it. A view from a provider the normalizer does not verify carries `"unverified": true`.
- `evidence coverage` prints, per provider and CLI version, the share of normalized events whose kind is not `unknown` and the most common `unknown` native types, and a count of records skipped for an unknown major version.

Capture is always on, so these verbs are not behind `training_data.enabled`.

## Boundary contract
### Evidence command group
- disposition: create
- owner: clutch/__main__.py
- consumers: operators, `clutch help`, `docs/how-clutch-works.md` section 2 and `clutch/docs/host-running.md` verb tables
- observable change: `clutch evidence show|schema|renormalize|coverage` exist. `show` and `schema` write nothing. `renormalize` writes only `normalized/*.json` and blobs under `<state_dir>/evidence/`. `coverage` writes nothing. Unknown call key, unknown record name or unreadable store exits 2 with a paved road, never a traceback. No lock, no journal event.
- compatibility: no existing verb changes; `training` is untouched
- acceptance: parser accepts exactly the four verbs, `schema` accepts exactly `start`, `end`, `event`; every command carries the `_command` help fields
- tests: tests/unit/test_main_evidence_group.py and tests/integration/test_evidence_verbs.py
- post-merge source of truth: clutch/__main__.py
- closest existing: the `training` group in `clutch/__main__.py`
- earning reason: `training` verbs are refused unless `training_data.enabled` and are about exported datasets; these verbs inspect always-on capture, and the CLI rule requires every command to sit in a fitting group

### Evidence views
- disposition: create
- owner: clutch/evidence/views.py
- consumers: the `show`, `renormalize` and `coverage` handlers
- observable change: pure functions that pick the normalizer for a start record's provider (claude, codex, gemini; qwen uses the claude normalizer), build the normalized view dict, render `show` lines, and compute coverage
- compatibility: `clutch/training.py` keeps its own normalizer table; this ticket does not touch it
- acceptance: the view dict has `schema` `clutch.evidence.events/1.0`, `normalizer` id, `unverified` bool and `events` list of `Event` dumps by alias
- tests: tests/unit/test_evidence_views.py
- post-merge source of truth: clutch/evidence/views.py
- closest existing: clutch/evidence/store.py, which persists records through the FileSystem seam only; clutch/training.py, which selects normalizers privately for export
- earning reason: three production consumers (the three verbs) share the selection and view building; putting them in the store would mix persistence with interpretation

### Normalized view storage
- disposition: extend
- owner: clutch/evidence/store.py
- consumers: `renormalize`, `show`, `coverage`, and the existing `EvidenceStore.prune`, which already reads `normalized/`
- observable change: `EvidenceStore` gains `write_normalized(key, normalizer_id, view)` and `read_normalized(key)`. The file name is the URL-quoted normalizer id (`claude-stream%2F2.json`). `read_normalized` returns views for ids of any version and skips a view whose `schema` has an unknown major version.
- compatibility: existing records, blobs and `prune` behavior preserved; prune still finds blob refs in `normalized/`
- acceptance: write then read returns the same view; a second id coexists; a major-2 view is skipped
- tests: tests/unit/test_evidence_normalized_store.py
- post-merge source of truth: clutch/evidence/store.py

### Normalizer verification flag
- disposition: extend

- observable change: each module gains `VERIFIED_PROVIDERS = frozenset({"<its provider>"})`, as `clutch/evidence/claude.py` already has
