The proposal is for `clutch lint` to suggest a successor path when a ticket names a file that no longer exists but exactly one file elsewhere in the tree has the same basename. It follows tree moves (eval/ to tests/harness/, flat tests/ to tests/integration/, docs/ to clutch/docs/) that left five committed tickets invalid. Lint reported only that each Context path did not exist, so each ticket needed hand investigation.

Lint behaves correctly today. It refuses a Context entry that does not exist (`clutch/tickets.py:379-386`), and the finding already gives a paved road. The note asks for a better diagnostic message, not a fix to wrong runtime behavior. The motivating incident is closed: none of the clutch-ruff-* ticket directories exist on main any more, and commit c09d48e0 removed the renamed ticket directories. Half of the proposal also has nothing to attach to. `## Scope fence` has no existence check, and it must not have one, because a fence legitimately names files the ticket will create, so a basename-successor hint there would mislead. The cost was one-off operator time after a batch of deliberate tree moves. No run failed and no stem was held wrongly. Reopen if another tree move leaves committed tickets invalid and investigating stale Context paths costs real time again, or if a run is lost because an agent or Author could not find the moved path.
