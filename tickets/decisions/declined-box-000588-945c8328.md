Once the open evidence-envelope ticket merges, every call's end.json will record rusage as null. The exec seam spawns children through asyncio, and asyncio reaps them with os.waitpid before os.wait4 could read per-child resource usage. The proposal is to have the exec seam reap children itself (Popen, a pidfd and os.wait4), keep the group-kill and drain contracts, pass rusage to CliAdapter.invoke without adding a new exec.run keyword, and move the tests/waiting.py spawn hook along with it.

This is a follow-up that the open ticket evidence-envelope already plans. That ticket has not merged. Its Goal says rusage is not delivered and points to the Suggestion Box for the follow-up, its Scope out excludes measuring rusage, and its acceptance criteria require rusage to be null. So no current runtime behavior is wrong: today no end.json exists, and after the merge a null rusage is the documented contract, not a defect. The message names no run or diagnosis that went wrong because rusage was missing. Missing evidence makes things less observable, but it does not cause incorrect behavior. The fix would also change the process-exec seam that every provider and git call uses, along with its group-kill and timing contracts, so it is a large redesign driven by an evidence-plan wish rather than a bounded repair. A bootstrap 'planned follow-up waiting on open tickets' message was declined the same way (declined-box-000587-1bd33bef). Reopen once evidence-envelope has merged and a diagnosis, retro or evidence consumer shows that the missing rusage hid or misattributed a failure, for example resource exhaustion read as a model failure. Also reopen if the 0.3.0 release acceptance review lists per-call rusage as an unmet promise of roadmap row 29.
