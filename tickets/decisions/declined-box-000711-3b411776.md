The shared CLI help helper `_command` in `clutch/__main__.py` prints the command's general description under every example, where each example should have its own one-line explanation. A command with two examples therefore shows the same sentence twice and never says what makes each example different. The merged cli-help-standard ticket asked for an explanation per example.

The mismatch is real. `_command` builds the help footer as `f"{example}\n  {does}"` and takes `examples` as plain strings. The cli-help-standard Scope in asks for each example to be a `clutch ...` invocation with its own one-line explanation. The harm, though, is limited to help wording. Every example is still a valid command, and the repeated sentence correctly describes the command. Nothing runs incorrectly and no decision depends on this text. The urgency in the message is also out of date: it asks for a fix before roadmap rows 130-140 write their examples, but the cli-group-* tickets for those rows (box, config, coverage, engine-control, engine-run, host, provider, release, ticket-authoring, ticket-verdicts, view) have all merged, so their examples already use this helper. This is help-text polish and a spec-wording mismatch, which falls under declined. Reopen if a person or agent is shown to run the wrong command or misread a command because example explanations are missing. Also reopen if a release audit counts per-example explanations as a ship condition.
