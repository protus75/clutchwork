`run_gate` in `clutch/roadmap.py` (line 405) runs every release gate command with `child_env(checkout.env, checkout.config)`. That strips configured provider auth keys. A gate command that calls a model, such as the planned `clutch roadmap accept <release>`, could not reach a provider that authenticates through a configured `auth` env key. The message asks either to give such a command its serving provider's key or to have the gate name the verbs that may receive one.

Nothing goes wrong today, so this is speculative hardening. `clutch roadmap accept` does not exist yet: open ticket `roadmap-accept` builds it, and open ticket `release-acceptance-review` adds it to the gate blocks. No gate command calls a model now. The message itself says the path works for claude and codex because they use ambient CLI login. The `roadmap-accept` ticket names this exact limit in its Scope out and leaves it for later, so no current run is harmed. Reopen if both tickets merge and a host that authenticates its judge through a configured `auth` env key gets an auth_error from `roadmap accept` run as a gate line. Also reopen if any other gate command that calls a model fails for the same reason.
