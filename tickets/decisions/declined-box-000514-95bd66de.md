The `confirm` and `reject` verbs always journal `reject_verdict` with `actor: operator` (`clutch/runner.py` lines 599 and 613), and a confirmed draft is journaled as a `draft_confirmed` signal with no actor at all. The message expects that, under driver plan open decision 5, a supervising agent loop will run these verbs with `--yes`. If it does, the journal cannot tell that loop's verdicts apart from a person's. The 0.3.0 ship gate and the planned `roadmap merged --unattended` filter both rely on that difference, so rows the loop released would count as attended.

Nothing goes wrong at runtime today, so this is declined. (1) The behavior that would cause the mix-up is still forbidden on main. CORE_TEMPLATE's supervising-session rule and `clutch/specs/ask/drain-loop.md:19` ('Never run `confirm` or `reject`, and never pass `--yes`') stop any session or loop from confirming or rejecting. Today every `actor: operator` verdict comes from a person, which is exactly what the label says. Decision 5 exists only in the confirmed but unmerged ticket roadmap-no-human-gates. That ticket's Scope out keeps the ban and sends the change to box-000508, which was declined because no driver-loop ticket exists yet (roadmap row 93 is unauthored). (2) Nothing that reads the actor exists yet either. `clutch/roadmap.py` does not exist. The `--unattended` filter is part of the open ticket roadmap-merged-query, which depends on two unmerged tickets (roadmap-table-parser and roadmap-author). The gate's command lines belong to the open ticket release-gates-as-commands. The ship gate on main is still prose. (3) The problem is real for the future, but the fix belongs with the loop that will run the verbs. It needs a way to record a non-operator actor, such as a flag the loop passes or a separate verb path. That change and the drain-loop/CORE_TEMPLATE rewrite should be written together in driver-loop, or ordered in its `## Runs before`. A separate ticket written now would change the verb's journal shape before any caller needs it. The same reasoning declined box-000508, box-000501 and box-000502. A related actor mislabel (machine kills recorded as `actor: operator`) was declined as box-000471. Reopen when driver-loop is about to be authored, or when a merged change lets any agent run `confirm`/`reject`. At that point, refile so the actor recording is fenced into driver-loop or into a ticket listed in its `## Runs before`. Also have roadmap-merged-query's `--unattended` filter key on that actor, or on a field that tells a loop-issued `draft_confirmed` apart from a person's.
