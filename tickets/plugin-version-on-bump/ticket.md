## Goal / Why
`docs/antigravity-plan.md` Target design section 6 and `tests/integration/test_antigravity_bundle.py` require the committed portable Antigravity plugin bundle (`plugin.json`, `mcp_config.json`, `assets/logo.png`, and `skills/clutch-*/SKILL.md`) to match `clutch/antigravity.py::portable_bundle_files(version_str=..., logo_bytes=...)` at the `pyproject.toml` version. Today `clutch/release.py::release` bumps only `pyproject.toml`, `uv.lock`, and `CHANGELOG.md`, so releasing `0.7.0` leaves `plugin.json` at `0.6.1` and immediately fails the drift test.

When `clutch release bump` runs in a repository carrying ClutchWork's committed portable plugin bundle (`plugin.json` with `"name": "clutchwork"` and `clutch/assets/logo.png`), regenerate every file from `clutch/antigravity.py::portable_bundle_files(version_str=version, logo_bytes=logo_bytes)` at the bumped version and include those paths in the dirty-file precheck and single `release: <version>` commit. Repositories without that committed bundle keep their existing 3-file commit unchanged.

## Boundary contract

### Release bump workflow (`clutch/release.py::release`)
- disposition: extend
- owner: clutch/release.py
- consumers: `clutch release bump` and `clutch release ship` (`clutch/__main__.py`, `clutch/roadmap.py`)
- observable change: when `repo / "plugin.json"` is a JSON object with `"name": "clutchwork"` and `repo / "clutch/assets/logo.png"` is readable via `fs.read_bytes`, `release()` checks `["pyproject.toml", "uv.lock", "CHANGELOG.md", *sorted(bundle)]` in `git.status_porcelain` before bumping, writes every entry from `portable_bundle_files(version_str=version, logo_bytes=logo_bytes)` via `fs.write` after `uv version --bump` and `CHANGELOG.md`, and commits all of them together in `git.commit(..., only=...)` before tagging.
- compatibility: function signature and `(version, sha)` return value are unchanged; repositories without ClutchWork's committed plugin bundle (missing `plugin.json`, invalid or non-object JSON, different `"name"`, or missing `clutch/assets/logo.png`) keep the exact 3-file dirty check, refusal message, writes, and `only=["pyproject.toml", "uv.lock", "CHANGELOG.md"]` commit list.
- acceptance: bundle-present release regenerates all bundle files at the bumped version and commits them atomically with the version files; dirty bundle files refuse before `uv version --bump`; non-bundle repos are unaffected.
- tests: `tests/unit/test_release_plugin_bundle.py`, `tests/unit/test_release.py`, `tests/unit/test_release_changelog.py`, `tests/integration/test_release.py`, `tests/integration/test_antigravity_bundle.py`
- post-merge source of truth: clutch/release.py

### Portable plugin bundle generator (`clutch/antigravity.py::portable_bundle_files`)
- disposition: reuse
- owner: clutch/antigravity.py
- consumers: `clutch/release.py::release`, `tests/integration/test_antigravity_bundle.py`, `tests/unit/test_antigravity_bundle.py`
- observable change: none; `clutch/release.py` calls `portable_bundle_files(version_str=version, logo_bytes=logo_bytes)` directly as the single source of truth for the committed bundle files.
- compatibility: unchanged signature and output bytes.
- acceptance: regenerated bytes written by `release()` equal `portable_bundle_files(version_str=version, logo_bytes=logo_bytes)` byte-for-byte.
- tests: `tests/unit/test_release_plugin_bundle.py`, `tests/integration/test_antigravity_bundle.py`
- post-merge source of truth: clutch/antigravity.py

## Scope in / Scope out
Scope in:
- `clutch/release.py`: detect ClutchWork's committed portable plugin bundle through `fs.read_bytes` (`repo / "plugin.json"` parses as a JSON object with `name == PLUGIN_NAME` and `repo / "clutch/assets/logo.png"` is readable via `fs.read_bytes`). When present, include `sorted(portable_bundle_files(version_str="", logo_bytes=logo_bytes))` in the `git.status_porcelain` dirty check (refusing before `uv version --bump` if any bundle file has uncommitted edits), write every `(rel, data)` from `portable_bundle_files(version_str=version, logo_bytes=logo_bytes)` via `fs.write(repo / rel, data)` after `uv version --bump` and the changelog write, and pass the three base release files plus `*sorted(bundle)` as `only=` to `git.commit`. When absent, preserve the exact 3-file dirty check, refusal text, writes, and `only=` list.
- `clutch/__main__.py`: update `release bump` command help (`does`, `reads`, `writes`) to note that when the committed Antigravity plugin bundle is present, it is checked for uncommitted edits, regenerated at the bumped version, and included in the release commit.
- `clutch/docs/host-running.md`: update the `release bump` verb row to note regenerating and committing the Antigravity plugin bundle when present.
- `docs/how-clutch-works.md`: update the `release bump --minor|--patch` row in section 2 to note plugin bundle dirty-checking, regeneration from `clutch/antigravity.py::portable_bundle_files`, and inclusion in the release commit when present.
- `tests/unit/test_release_plugin_bundle.py`: new unit test file using fakes/`tmp_path` only (no repo file reads, no subprocesses, no network) covering bundle regeneration and commit path list, dirty bundle file refusal before `uv version --bump` and before any write, non-bundle detection cases (missing `plugin.json`, invalid JSON, non-ClutchWork `plugin.json`, missing `clutch/assets/logo.png`), and keeping `clutch/release.py` at or above its 90% default unit coverage floor in `test-gate.toml`.

Scope out:
- Do not modify `clutch/antigravity.py`, `clutch/roadmap.py`, `plugin.json`, `mcp_config.json`, `assets/`, or `skills/`.
- Do not modify `tests/unit/test_release.py`, `tests/unit/test_release_changelog.py`, `tests/integration/test_release.py`, or `tests/integration/test_antigravity_bundle.py`.

## Acceptance criteria
1. When a repository contains `plugin.json` with `"name": "clutchwork"` and `clutch/assets/logo.png`, `clutch/release.py::release` writes every file returned by `portable_bundle_files(version_str=version, logo_bytes=logo)` with `plugin.json["version"] == version` (not the previous version) before committing, and passes `["pyproject.toml", "uv.lock", "CHANGELOG.md", *sorted(bundle)]` as `only=` to `git.commit` (not only the three base files): verified by `./dev.py test tests/unit/test_release_plugin_bundle.py`.
2. When any plugin bundle file is reported dirty by `git.status_porcelain`, `clutch/release.py::release` raises `Refusal` before running `uv version --bump` or writing `CHANGELOG.md` or any bundle file (not overwriting or committing uncommitted bundle edits): verified by `./dev.py test tests/unit/test_release_plugin_bundle.py`.
3. When a repository does not carry ClutchWork's committed plugin bundle (missing `plugin.json`, invalid JSON, `plugin.json` with a different `"name"`, or missing `clutch/assets/logo.png`), `clutch/release.py::release` checks and commits only `["pyproject.toml", "uv.lock", "CHANGELOG.md"]` and writes no bundle files (not creating or staging `plugin.json` in unrelated host repos): verified by `./dev.py test tests/unit/test_release_plugin_bundle.py tests/unit/test_release.py tests/unit/test_release_changelog.py tests/integration/test_release.py`.
4. `clutch release bump` CLI help in `clutch/__main__.py`, the verb row in `clutch/docs/host-running.md`, and the section 2 row in `docs/how-clutch-works.md` document the plugin bundle regeneration on bump without breaking help checks or the committed bundle drift test: verified by `./dev.py test tests/unit/test_main_help.py tests/unit/test_help.py tests/integration/test_help.py tests/integration/test_antigravity_bundle.py`.
5. `clutch/release.py` maintains at least its 90% default unit coverage floor in `test-gate.toml` with all new tests in `tests/unit/test_release_plugin_bundle.py` using fakes/`tmp_path` only: verified by `./dev.py test tests/unit/test_release.py tests/unit/test_release_changelog.py tests/unit/test_release_plugin_bundle.py`.
