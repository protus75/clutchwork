A0 fact 01: result-event-shape
gemini-cli 0.49.0, captured 2026-11-15 (UTC 2026-11-16).

FINDING
stream-json (-o stream-json) is JSONL on stdout, one event per line, types: init, message, tool_use,
tool_result, error, result.
- init: {type, timestamp, session_id, model}. `model` is the -m string as given, before the CLI's
  model resolution (see fact 12).
- message: {type, timestamp, role: "user"|"assistant", content, delta?}. The user prompt is echoed
  once (role user, delta absent). Reply text arrives as role "assistant" chunks with delta:true;
  the full reply is the concatenation of every assistant `content` in order. There is no
  final-message event and the result event carries no reply text.
- tool_use: {type, timestamp, tool_name, tool_id, parameters}; tool_result: {type, timestamp,
  tool_id, status, output?}. tool_result.output is absent or a short display string (read_file
  output was ""), never the full tool output. tool_id pairs them.
- error: {type, timestamp, severity, message}. Seen only for "Invalid stream" (fact 2/7).
- result (terminal): success = {type, timestamp, status:"success", stats}; failure =
  {type, timestamp, status:"error", error?:{type, message}, stats}. stats = {total_tokens,
  input_tokens, output_tokens, cached, input, duration_ms, tool_calls, models:{<served model>:
  {total_tokens, input_tokens, output_tokens, cached, input}}}. input_tokens = prompt incl. cached;
  input = input_tokens - cached; output_tokens excludes thinking; thinking (plus tool) tokens are
  only derivable as total_tokens - input_tokens - output_tokens. `models` keys are the API's
  response modelVersion, which can differ from init.model (fact 12).
json (-o json): one pretty-printed object on stdout at the end: {session_id, response (full reply
text, ANSI stripped), stats:{models:{<model>:{api:{totalRequests,totalErrors,totalLatencyMs},
tokens:{input,prompt,candidates,total,cached,thoughts,tool}, roles:{main:{...}}}}, tools:{...},
files:{totalLinesAdded,totalLinesRemoved}}}. json reports thoughts explicitly. On failure stdout
is EMPTY and {session_id, error:{type,message,code}} goes to STDERR (fact 2, run t05).
Source: StreamJsonFormatter / JsonFormatter in bundle/chunk-VLV2BYPM.js (~line 369000).
