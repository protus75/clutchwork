A0 fact 10: headless-prompt-delivery
gemini-cli 0.49.0, captured 2026-11-15 (UTC 2026-11-16).

FINDING
The digest's worry is unfounded: -p is NOT required. With stdin and stdout not a TTY the CLI runs
headless and reads the whole prompt from stdin (t10; source isHeadlessMode: non-TTY stdin OR
stdout, -p, a positional query, or CI=true). With both, the prompt is `<stdin>\n\n<-p value>` (t11).
Limits: stdin is read up to 8 MiB (MAX_STDIN_SIZE = 8*1024*1024; the excess is silently truncated
with only a debug warning). stdin must deliver its first byte within 500 ms of the CLI starting to
read it, or the CLI treats stdin as empty: a prompt written 5 s late gave exit 42 "No input provided
via stdin" (t12). A -p argument is capped by Linux MAX_ARG_STRLEN: 131071 bytes exec'd, 131073 bytes
failed with E2BIG before the CLI ran. So the adapter should write the prompt to stdin immediately
at spawn and close it, with no -p.
