FINDING
-m is NOT a literal pin. The CLI resolves the name first (resolveModel / modelIdResolutions in
chunk-VLV2BYPM.js ~270252 and ~349570): when the account has Gemini 3.5 Flash GA access, any name
ending in "flash" (gemini-2.5-flash, gemini-3.8-flash, alias "flash") is rewritten to
gemini-3.5-flash, which the API then served as gemini-3.6-flash. Aliases auto/pro resolve to
gemini-3.1-pro-preview with API-key auth (source only, not run). Names the CLI does not know pass
through unchanged: gemini-3.1-flash-lite, gemini-3.1-pro-preview, gemini-2.5-flash-image,
gemini-3.1-flash-image-preview. A typo passes through and fails at the API (fact 02).
Three different names describe one call: init.model = the -m string; the session record "model" =
the resolved request model; result.stats.models key = the API's response modelVersion (the model
actually billed). t02: gemini-2.5-flash / gemini-3.5-flash / gemini-3.6-flash. The adapter should
record the stats key as the served model.
