A0 fact 07: image-generation-headless
gemini-cli 0.49.0, captured 2026-11-15 (UTC 2026-11-16).

FINDING
NEGATIVE as an output contract. The CLI can CALL an image model headlessly only after a settings
file removes every tool and replaces the model's generation config, and even then it THROWS THE
IMAGE AWAY: no image on stdout (stream-json or json carry text only), no file written, no image in
the session record (~/.gemini/tmp/<project>/chats/*.jsonl). Steps observed:
- t23: -m gemini-2.5-flash-image with tools (any grant) -> HTTP 400 "Function calling is not
  enabled for this model", exit 144. The image model cannot call write_file, so it can never save
  a file itself.
- t24: tools.core: [] -> HTTP 400 "Thinking is not enabled for this model" (an unknown model name
  inherits the CLI's chat-base alias with thinkingConfig), exit 144.
- t25: + modelConfigs.customAliases["gemini-2.5-flash-image"] (no extends, responseModalities
  [TEXT, IMAGE]) -> success, 1302 output tokens (one image is ~1290), reply text "Here it is:", image
  dropped.
- t26: same + 2 input images referenced in the prompt as @red-circle.png @blue-square.png (the
  @path reader inlines images as inlineData, even with no tools registered) + a telemetry outfile
  with logPrompts: true -> the image bytes appear ONLY base64-encoded inside the telemetry record's
  response_text attribute (1.27 MB OTel debug log). Extracted: fact-07-generated-fusion.png,
  1024x1024 PNG, correct fusion.
- t28: 4 input images (above the "3" in the owner notes) were accepted and fused
  (fact-07-generated-4-inputs.png), but the reply had no text part, so the CLI reported
  "Invalid stream: The model returned an empty response or malformed tool call", result.status
  error, exit 0, although a valid image was returned and billed.
- t27: gemini-3.1-flash-image-preview accepts tools and thinking, generated an image (1406 output
  tokens), and the CLI again reported "Invalid stream" with exit 0.
Input images: @path in the prompt (png/jpg/gif/webp, by mime type; svg is read as text). Input
limit: no CLI-side cap observed; 4 inputs worked on gemini-2.5-flash-image. Output format when
recovered: image/png, 1024x1024.
Conclusion: Part B's assumption ("Gemini CLI can call an image model headlessly and write the
result to a file") is false. The only CLI route to the bytes is scraping a telemetry debug log,
which is not an interface, also captures the whole prompt, and fails on image-only replies.
`api-provider-client` (roadmap row 56) is NEEDED.
