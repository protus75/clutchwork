`Serve.intake_snapshot` (clutch/serve.py 287-301) returns (listing of tickets/, every ticket file's contents, `git status` of tickets/, the sha of main, and the last journal state of pending stems). `Serve.scan` (303-315) enters `async with self.mutations():` (`admission.exclusive()`, clutch/daemon.py 596-601: waits until no run holds a slot and, while waiting, refuses new runs) whenever the snapshot differs from the previous one.

The sha of main changes on EVERY commit to main: the engine's own run-record, checks, harvest, diagnosis, review and merge commits, the roadmap driver's link, strike and refile commits, and an operator's ticket-plane commits. In 2026-11-21's log those happen every few minutes, so the scan takes the exclusive section (waiting for every running implementation, blocking admission meanwhile) far more often than a ticket file really changed.

Why the sha is in the snapshot: ticket serve-polls-block-parallel-runs (merged) added it so a ticket that intake REFUSED because of repo state outside tickets/ (for example a context or fence path a merge added under clutch/) is retried after main moves. A refused ticket stays an uncommitted file under tickets/, so it appears in `pending` (`_pending(c.repo, _porcelain(status))`, the same function already used for the journal-state part of the snapshot). With no pending uncommitted ticket file there is nothing to retry, and a move of main cannot change what intake does.

Not changed here (larger, riskier, separate): the exclusive section also keeps intake away from engine writers that write a ticket file and then commit it outside any shared lock: verdict confirm and reject (clutch/runner.py 710-711, 739-740, 823-824), rework publish (clutch/daemon.py 408-411) and Author publish (clutch/author.py 507). Removing the exclusive section from scan needs all of them under one lock.
