Assume the reader knows what they want to accomplish but may be new to the workflow. Start at the entry point they can actually use. State the prerequisite, give the action in the product’s own words, and describe the next visible result. Name the role responsible when control passes to someone else.

For Clutch, use the supported operator verb or UI label in the supplied material. When an action is refused, explain the reason and the documented way forward. Include technical detail when the reader must act on it, such as an exit code consumed by their script. Preserve release and availability conditions.
