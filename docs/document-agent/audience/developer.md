Assume language and tooling fluency, but explain this project’s ownership and composition. Name the canonical symbol, command, or schema and a real consumer from the supplied material. Trace a representative call or read. Specify the inputs, results, and failure behavior the consumer can observe, including compatibility when an existing consumer must migrate.

For a change, identify the supported seam and a verification case that distinguishes a correct implementation from a plausible wrong one. Keep names consistent across prose, signatures, and examples. When sources leave an observable decision unresolved, identify the consumer affected and the decision needed.
